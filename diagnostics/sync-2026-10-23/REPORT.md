# Замеры синхронизации Ambilight — 23 октября 2026

Исправлена программная рассинхронизация: общий неизменяемый кадр для всех
устройств, общая частота обновления, компенсация измеренных задержек. Опция
`sync_devices` включена в конфигурации и по умолчанию в GUI/CLI. Между двумя
ARGB-зонами MSI остаётся около 93 мс: используемый драйвер отправляет два
отдельных последовательных HID-отчёта и не реализует общий latch/apply.

## Методика

Замерены реальные вызовы `DeviceUpdateLEDs()` внутри OpenRGB, а не только
отправка TCP-пакетов из Python. Для MSI отдельно измерен каждый HID-отчёт
JARGB2/JARGB3. Начало и длительность записаны по монотонным часам вместе
с цветом. Сопоставление — по одному и тому же уникальному входному цвету;
повторный keep-alive не считается новым переходом.

Это измерения завершения аппаратных записей, **не оптический замер свечения**.
Внутренняя задержка прошивки после принятия отчёта не измерена.

Во время проб обычный Ambilight был остановлен, чтобы два клиента не
перезаписывали друг другу цвета. Устройства и размеры зон сохранены:

- Kingston Fury DDR5 DRAM: 24 LED, два модуля по 12.
- XPG Summoner: 104 LED.
- MSI MYSTIC LIGHT (761-byte): JAF=0, JARGB1=0, JARGB2=60, JARGB3=60.
- Roccat Burst Pro: 2 LED.

Ступенчатый сигнал: 20 цветов, по одному каждые 650 мс.
Исходная настройка — `sync_devices=false`.

до завершения аппаратной записи.

При исправленном Sync — по 48 записей на каждое устройство, последовательности
RGB полностью совпадают, изменений цвета в процессе записи — 0.

## Что изменено

- Один выбранный RGB сохраняется до отправки всем устройствам; более свежие
  входные цвета ждут следующего общего аппаратного кадра.
- Отправки планируются по общей целевой отметке времени. Для MSI с двумя
  активными зонами используется середина двух записей — 138,75 мс, а для
  ограничения нагрузки учитывается полное время занятости 185 мс.
- С учётом коэффициента нагрузки 1,5 общий интервал составляет 277,5 мс
  (около 3,6 FPS). Частота захвата экрана остаётся 60 FPS. Синхронность требует
  пропускать промежуточные кадры одинаково на всех устройствах.
- Пропущенная из-за занятого сокета отправка повторяется; она больше не
  помечается как выполненная. Первый кадр тоже учитывает компенсацию.
- Переключение Sync завершает текущий общий кадр. Потеря резервной HID-
  клавиатуры не блокирует обновления остальных устройств.
- `--test` использует тот же планировщик; `--no-sync` оставлен для независимых
  обновлений. Текст настройки GUI описывает компромисс по частоте.
- В OpenRGB добавлена диагностическая трассировка `FrameTiming`/`ZoneTiming`.
  В обычном режиме loglevel=3 она отключена.

11 регрессионных тестов прошли: общий кадр, частота, первая отправка,
повтор при занятом сокете, последний цвет после остановки входного потока,
переключение Sync, keep-alive, отключение HID, пакет SDK, расчёт задержки зон.

Полная одновременность всех светодиодов не подтверждена и не обещается:
последовательные зоны MSI и переменная задержка SMBus остаются ограничениями
нынешнего пути управления. Драйвер MSI в этой работе не менял протокол записи.

## Воспроизведение и откат

Остановить обычный Ambilight. Установить `LogManager.loglevel=4` в
`OpenRGB-patched/config/OpenRGB.json`, перезапустить задачу
`OpenRGB (elevated)`. Из корня проекта, Python с установленными зависимостями:

```powershell
python tools/measure_sync.py --sync --pattern stream --seconds 13 --output stream.json
python tools/measure_sync.py --sync --pattern steps --seconds 13 --output steps.json
python -m unittest discover -s tests -v
```

В этой системе зависимости находятся в
`C:/Users/vadso/AppData/Local/Python/pythoncore-3.14-64/python.exe`.
После замеров вернуть loglevel=3 и перезапустить OpenRGB и Ambilight.

Исходный Python-файл и настройки сохранены рядом: `Ambilight.before.pyw`,
`config.before.json`, `OpenRGB.before.json`. Исходный бинарник —
`OpenRGB-patched/backup/OpenRGB.exe.bak-sync-20261023` от корня проекта.
Патч диагностики — `OpenRGB-patched/patches/frame-timing.patch`;
полный патч и портативная сборка обновлены.

Остальные JSON в этой папке — промежуточные измерения, включая вариант
выравнивания к концу последней зоны. Итоговая версия — `midpoint-*.json`.
