# OpenRGB (patched, portable)

OpenRGB 0.9+ (git1926, коммит `f89cdac`) с патчами под этот ПК. Папка
самодостаточна: её можно переносить или копировать целиком.

## Ambilight встроен (с 2026-11-22)

Ambilight теперь работает внутри этого OpenRGB как плагин
`plugins\OpenRGBAmbilightPlugin.dll` (исходники и сборка: `..\plugin\`).
Отдельный Python-скрипт больше не нужен и в автозапуске его быть не должно.

- Вкладка **Ambilight** в окне OpenRGB: Старт/Стоп, статус, цвет на
  подсветке и все настройки старого окна (применяются сразу и сохраняются).
- Меню значка OpenRGB в трее → **Ambilight**: Старт/Стоп, музыкальный режим,
  настройки.
- **Ctrl+Alt+A** — включить/выключить откуда угодно.
- Запускается вместе с OpenRGB (галочка «Start Ambilight when OpenRGB
  starts»), дальше работает расписание (старт 18:00, стоп 02:00).
- Настройки: `config\plugins\settings\Ambilight.json` (при первом запуске
  перенесены из `..\config.json`), журнал: `config\logs\Ambilight.log`.
- Включается/выключается в «Настройки → Plugins».
- `OpenRGB.exe` двойным щелчком (и ярлык `..\Ambilight.lnk`) теперь
  показывает окно уже работающего OpenRGB, а не открывает вторую копию.

## Портабл

- Все настройки, размеры зон (`sizes.ors`), профили и логи лежат в `config\`
  рядом с `OpenRGB.exe`. В `%APPDATA%\OpenRGB` ничего не пишется (старая папка
  там осталась как резервная копия, программа её больше не читает).
- Ключи `--config <папка>` и `--localconfig` по-прежнему переопределяют это.
- Логи хранятся максимум 10 последних (`config\logs`).

## Чего портабл не отменяет

- **Драйвер PawnIO** (служба `PawnIO`) должен быть установлен в системе — без
  него нет SMBus и не видна RGB-память. Установщик: `PawnIO_setup.exe -install -silent`
  (github.com/namazso/PawnIO.Setup).
- OpenRGB должен работать **с правами администратора** — иначе тоже нет RAM.

## Автозапуск

Запускается задачей планировщика **«OpenRGB (elevated)»** при входе в систему
(через 10 с, с повышенными правами):
`OpenRGB.exe --startminimized --server --noautoconnect`.

- После переноса папки запустите `register-autostart.ps1` — он перерегистрирует
  задачу на `OpenRGB.exe` рядом с собой (спросит UAC) и уберёт другие автозапуски
  OpenRGB (ярлык в «Автозагрузке», старую службу OpenRGB).
- `OpenRGB.exe` можно запускать двойным щелчком: он не запускает вторую
  копию, а показывает окно работающего сервера (сигнал через именованное
  событие `Local\OpenRGB_ShowWindow`) и сразу закрывается. Если сервер ещё не
  работает, сначала запускает задачу и показывает окно, когда устройства
  найдены. Это работает и с правами администратора — у `OpenRGB.exe` здесь
  стоит флаг совместимости «Запускать от имени администратора». Если задачи
  нет (папку перенесли), обычный запуск попросит UAC.
- Крестик на окне сворачивает OpenRGB в трей (`minimize_on_close`); полностью
  выходить — через «Выход» в меню значка в трее. Перезапуск сервера:
  `schtasks /run /tn "OpenRGB (elevated)"`.
- Галочку «Запускать при старте системы» в настройках OpenRGB не включайте: она
  создаёт ярлык в «Автозагрузке» без прав администратора и второй экземпляр.

## Что изменено в этой сборке

Полный патч относительно `f89cdac`: `patches\openrgb-patched-full.patch`.

Для плагина Ambilight (2026-11-22, `patches\ambilight-plugin-host.patch`):
- PluginManager: новый плагин наследовал флаг `enabled` последнего плагина
  из списка в `OpenRGB.json` (здесь — выключенного Effects Plugin) и
  регистрировался выключенным. Теперь учитывается только его собственная запись.
- Один экземпляр: повторный запуск `OpenRGB.exe` выводит окно работающего
  экземпляра вместо окна-клиента (в котором плагины запустились бы второй раз).
- Пересканирование, запрошенное, пока предыдущее обнаружение ещё
  завершается (например, после «Остановить обнаружение»), игнорируется с
  предупреждением в логе. Раньше оно отдавало слушателям старый список
  устройств и тут же удаляло его — плагин писал бы в удалённые объекты.
- `RGBController`: список колбэков обновления меняется только под
  `UpdateMutex` — тем же мьютексом, под которым его обходят потоки SDK и плагина.

Функциональные исправления (раньше):
- XPG Summoner: цвета отправляются HID feature report (иначе клавиатура не
  управляется) + keep-alive, иначе подсветка гаснет через ~2 с.
- Kingston Fury DDR5: одна задержка 10 мс на кадр вместо 36 (кадр 380 → ~95–140 мс).
- MSI Mystic Light 761: зоны размером 0 LED не отправляются (кадр 372 → 185 мс).
- `[UpdateTiming]` в логе при loglevel 4 — реальное время обновления каждого устройства.
- `[FrameTiming]` и `[ZoneTiming]` при loglevel 4 — время и цвет каждого кадра
  и каждой ARGB-зоны MSI. Патч поверх предыдущей сборки:
  `patches\frame-timing.patch`. В обычном режиме (loglevel 3) трассировка выключена.
  Замеры синхронизации: `..\diagnostics\sync-2026-10-23\REPORT.md`.

Производительность и портабл (2026-10-23):
- Потоки устройств ждут события вместо опроса флага каждую 1 мс:
  в простое ~6700 → ~5 переключений контекста в секунду.
- Системный таймер: 1 мс один раз вместо 0,5 мс из вечного цикла. 0,5 мс
  включается только на время записи кадра в RAM (её SMBus-запись тактуется таймером).
- Keep-alive клавиатуры шлёт кадр, только если ~0,8 с не было своих — не
  занимает USB-шину во время Ambilight.
- Кадр, пришедший во время записи в устройство, больше не теряется (флаг
  сбрасывается до записи, а не после) — последний цвет всегда доходит.
- GUI не перерисовывает скрытые страницы устройств на каждый кадр.
- SDK-сервер читает заголовок пакета одним вызовом, а не по байту.
- Пропуск шины I2C видеокарты AMD (ADL): `"Drivers": {"amd_adl_i2c": false}` в
  `config\OpenRGB.json`; на старте экономит ~1,4 с.
- Исправлена ротация логов: при `file_count_limit` OpenRGB удалял *все* старые логи.
- Запуск без прав администратора передаёт работу серверу с правами (см. «Автозапуск»);
  два экземпляра, стартовавшие в одну секунду, пишут в разные логи (`…_2.log`).

Настройки в `config\OpenRGB.json`:
- Включены только детекторы своих устройств (Kingston Fury DDR5, XPG Summoner,
  MSI Mystic Light X870/Common/MS_7E59, Roccat Burst Pro). **Новое RGB-устройство
  не найдётся**, пока не включить его в «Настройки → Supported Devices».
- Задача запускается с `--noautoconnect`: без него OpenRGB ~5 с ждёт таймаута,
  пытаясь подключиться к «другому себе».

Замеры (те же 4 устройства, стресс 60 кадров/с на все):

| | было | стало |
|---|---|---|
| Готов к работе после запуска | 9,0 с | 2,3 с |
| CPU в простое | 0,8–1,3 % ядра | ~0 % |
| Пробуждений потоков в простое | ~6700/с | ~5/с |
| Системный таймер в простое | 0,5 мс | 1 мс |
| Память (рабочий набор) | 46 МБ | 43 МБ |
| Кадр RAM / клавиатура / плата | 148 / 32,5 / 185 мс | 140 / 31,3 / 186 мс |

## Пересборка

Исходники и тулчейн MSYS2: `..\_orgb_build\`. Сборка: `_build_perf.sh`
(инкрементальная), выкладка: `_deploy.sh`, затем `_install_patched.ps1` — он
заменяет только бинарники, `config\` не трогает, старый exe кладёт в `backup\`.
Откат: остановить задачу, вернуть exe из `backup\`, запустить задачу.

Плагин Ambilight использует объекты OpenRGB напрямую, поэтому собирается тем
же тулчейном: `..\plugin\build.sh`, установка — `..\plugin\install-plugin.ps1`.
Если меняются `RGBController.h`, `ResourceManagerInterface.h` или
`OpenRGBPluginInterface.h`, пересобрать и установить и OpenRGB, и плагин.
